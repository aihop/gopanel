# GoPanel AI 任务契约

本目录保存可版本化的 AI 任务声明，用于在执行前明确目标、仓库范围、风险审批、验收证据和验证入口。

GoPanel 已经具备项目、多仓 worktree、长期会话、质量门禁、交付、审批、审计和手机任务摘要。任务契约用于补齐这些运行对象上游的“完成定义”，不替代数据库中的实时状态，也不另建执行链路。

## 目录

- `schema/task-v1.schema.json`：任务契约 v1 的机器可读结构。
- `tasks/*.json`：具体任务或示例。示例文件以 `.example.json` 结尾。
- `tools/contractcheck`：仓库内置的语义校验器。

## v1 分层

1. 仓库契约保存用户目标、允许变更的仓库和文件范围。
2. GoPanel 创建任务时，后续应把契约内容、版本和哈希固化为任务快照。
3. 执行过程继续使用现有会话、审批、质量检查、交付和审计表。
4. 验收结果后续按 `acceptanceCriteria[].evidence` 生成结构化报告，手机端展示摘要，详情保留原始输出。

当前第一期只实现仓库声明与静态校验，尚未把契约导入 `AITask`，也不会自动执行 `verification[].command`。命令字段只是声明；接入控制平面后，应优先引用项目已配置的质量检查，高风险或新增远程命令仍须走现有审批与审计。

## 必须声明

- `problem`：当前真实问题，不能只写实现方案。
- `expectedOutcome`：用户可观察到的闭环结果。
- `repositories`：逐仓声明归属、依赖关系、读取依据和允许修改范围。
- `risks`：远程执行、凭据、推送、合并、部署、数据库写入和破坏性动作。
- `acceptanceCriteria`：每项都必须声明可追踪的证据。
- `verification`：引用现有质量检查，或声明精确的命令、预览及人工核验入口。
- `mobileSummary`：适合手机首屏展示的目标、成功结果和需关注事项。

## 校验

```bash
go run ./tools/contractcheck
```

也可以只校验指定文件：

```bash
go run ./tools/contractcheck .ai/tasks/gopanel-task.example.json
```

校验器会拒绝未知字段、重复 ID、无证据的验收条件、越界的仓库引用，以及未要求审批的高风险动作。校验器不会执行契约中的任何命令。

新任务从示例复制后创建新文件，不要覆盖示例。路径应相对于对应仓库根目录；外部仓库可使用绝对路径，但必须由执行环境再次确认真实 Git 根目录和权限。

只用于核对事实、禁止修改的参与仓库应显式填写 `writeScope: []`，不能省略该字段。
